┌─────────────────────────────────────────────────────────────────────────────┐
│ SYSTEM ARCHITECTURE LAYERS                                                    │
└─────────────────────────────────────────────────────────────────────────────┘

1. USER INTERFACE LAYER
   ├─ FastAPI REST Endpoint (localhost:8000/search)
   ├─ Accepts queries: "Find unmet needs for Molecule X", etc.
   └─ Returns JSON with task_id for async tracking

2. ORCHESTRATION LAYER (Master Agent)
   ├─ Receives user query
   ├─ Uses LLM to decompose into subtasks
   ├─ Assigns tasks to appropriate worker agents
   ├─ Monitors progress in real-time
   └─ Synthesizes final report

3. WORKER AGENT LAYER (CrewAI Agents)
   ├─ IQVIA Insights Agent → Market data, trends, competition
   ├─ EXIM Trade Agent → Import/export data via API
   ├─ Patent Landscape Agent → USPTO, patent expiry analysis
   ├─ Clinical Trials Agent → ClinicalTrials.gov data
   ├─ Internal Knowledge Agent → PDF summaries from company
   ├─ Web Intelligence Agent → Scientific articles, regulatory info
   └─ Report Generation Agent → PDF conversion with charts

4. DATA SOURCE LAYER
   ├─ Public APIs:
   │  ├─ ClinicalTrials.gov API (no auth required)
   │  ├─ USPTO API
   │  ├─ PubMed Central API
   │  └─ WHO/EMA Regulatory Sites
   ├─ Subscription APIs (with mocked data):
   │  ├─ IQVIA (simulated)
   │  ├─ EXIM Trade Database (simulated)
   │  └─ PatentScope
   ├─ Internal Knowledge:
   │  └─ PDFs, documents, strategy docs (VectorDB)
   └─ Web Search:
      └─ Searx/Google Custom Search API

5. STORAGE & PERSISTENCE
   ├─ Vector Database (Chroma/FAISS) for documents
   ├─ Cache layer (Redis) for API responses
   ├─ File storage for generated PDFs
   └─ PostgreSQL for task history & metadata

User Query

Query: "Check current clinical trials for this mechanism"
├─ Master Agent decomposes to:
│  ├─ → Clinical Trials Agent: Get trials by mechanism
│  ├─ → Internal Knowledge Agent: Check prior company trials
│  ├─ → Web Intelligence Agent: Find summary articles
│  └─ → Report Agent: Create comparison table
└─ Output: Structured trial comparison with key metrics

Query: "Which diseases could this drug be repurposed for?"
├─ Master Agent decomposes to:
│  ├─ → Patent Agent: Verify patent status
│  ├─ → Web Intelligence Agent: Scientific literature mining
│  ├─ → Clinical Trials Agent: Trials mentioning similar mechanisms
│  ├─ → IQVIA Agent: Market attractiveness of target diseases
│  ├─ → Internal Knowledge Agent: Prior exploration by company
│  └─ → Report Agent: Ranked opportunity list
└─ Output: Top 10 repurposing opportunities with scores

┌─────────────────────────────────────────────────────────────────────────────┐
│ IMPLEMENTATION STACK                                                          │
└─────────────────────────────────────────────────────────────────────────────┘

Backend Framework:
├─ Framework: FastAPI (async, production-ready)
├─ Agent Orchestration: CrewAI + LangGraph
├─ LLM: OpenAI GPT-4 (primary), Claude 3 (fallback)
├─ Async Task Queue: Celery + Redis
└─ API Gateway: Uvicorn

Data Processing:
├─ Vector DB: Chroma (local) or Pinecone (cloud)
├─ Cache: Redis
├─ Database: PostgreSQL
└─ File Storage: MinIO or S3

APIs & Integrations:
├─ Public: ClinicalTrials.gov, USPTO, PubMed, WHO
├─ Mocked: IQVIA, EXIM, PatentScope (with sample data)
├─ Internal: PDF upload, document store
└─ Web: BeautifulSoup, Selenium for scraping

Report Generation:
├─ PDF: ReportLab
├─ Charts: Matplotlib, Plotly
├─ Tables: Pandas
└─ Storage: Local file system or S3

Monitoring:
├─ Logging: Python logging + ELK stack
├─ Tracing: LangSmith for agent monitoring
├─ Metrics: Prometheus + Grafana
└─ Error handling: Sentry

┌─────────────────────────────────────────────────────────────────────────────┐
│ SCALABILITY & PRODUCTION CONSIDERATIONS                                       │
└─────────────────────────────────────────────────────────────────────────────┘

Scaling Strategies:
├─ Horizontal: Load balance FastAPI instances
├─ Task Distribution: Celery workers for parallel agent execution
├─ Caching: Redis for API response caching (24h TTL)
└─ Database: Connection pooling, read replicas for analytics

High Availability:
├─ Multi-region deployment
├─ Failover for external APIs
├─ Circuit breaker pattern for external calls
└─ Graceful degradation (use cached data if API fails)

Cost Optimization:
├─ Use cheaper models for simple tasks (GPT-3.5)
├─ Batch API calls during off-hours
├─ Cache frequently accessed data
└─ Use mocked data for demo/testing

Security:
├─ API keys in environment variables
├─ VPC for database connections
├─ Role-based access control (RBAC)
├─ Input validation and sanitization
└─ Audit logging for all searches
